### Findings (ordered by severity)

**1. [Medium] [PRE-EXISTING] SpeciesPage.svelte (delete-list button, ~304-313): hover-only reveal with no keyboard-focus equivalent. Tag: objective, fixable.**
The button is `opacity-0 ... transition-opacity group-hover:opacity-100`, revealed only when the parent row is mouse-hovered. There is no `group-focus-within:` / `focus-visible:` counterpart. A keyboard user who tabs to this button gets nothing visible: the element (and its focus ring) stays at opacity 0, so the focused destructive control is invisible. User-visible consequence: keyboard-only users cannot see which delete control they are about to activate. Suggested fix (described, not applied): add `group-focus-within:opacity-100` on the button (and/or `focus-visible:opacity-100`) so the action reveals on keyboard focus as well as hover. This is the checklist item-5 "hover:-only reveal with no focus equivalent" pattern, and it is objective and mechanically fixable, so route to Agents 2/3.

**2. [Low] [PRE-EXISTING] LogPanel.svelte (clear-log button, ~93): destructive clear with no confirmation.**
`onclick={clearLog}` wipes the entire log in one click, no confirm step (unlike the Settings "clear all data" button, which opens a modal). Consequence: an accidental click discards the visible log. Mitigating context that keeps this Low and report-only (product judgment): log entries are ephemeral/non-critical, and a Copy-to-clipboard button sits immediately to its left, so the user can rescue the content first. Suggested consideration: a lightweight confirm, or an undo/toast, if logs are ever treated as important. Not the icon swap's concern.

**3. [Low] [PRE-EXISTING] SettingsPanel.svelte (clear-all button, ~903-910): disabled state has no discoverable reason. Tag: objective, fixable (minor).**
`disabled={clearing || appState.catalogStats.total_detections === 0}` with no `title` / `aria-describedby` tied to that condition. Consequence is small because the DB content counts (detections/species/locations) render directly above, making the "nothing to clear" state inferable visually. For contrast, `InstalledModelCard.svelte` handles the same situation correctly: its remove button swaps `aria-label`/`title` to `gallery_removeDisabledDefault()` when disabled. Suggested fix: mirror that pattern, give the clear-all button a `title` explaining the disabled reason when count is 0.

**4. [Low] [PRE-EXISTING] All 5 buttons: no `type="button"`. Tag: objective, fixable (very low impact here).**
None of the five buttons declares `type="button"`, so each defaults to `type="submit"`. I verified none of them sits inside a `&lt;form&gt;`: the only `&lt;form&gt;` elements in these files are the `method="dialog"` modal backdrops in SettingsPanel (972, 998) and SpeciesPage (531, 648), which do not wrap these buttons. **5. [Low / informational] [PRE-EXISTING] SpeciesPage.svelte (~276-313): nested interactive control.**
